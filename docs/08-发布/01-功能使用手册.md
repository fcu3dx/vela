## 二、v0.2.0 新增功能

### 2.1 多 Agent 协作体系

#### 概念
v0.2.0 引入 13 个专业化 Agent，每个 Agent 是独立的 AI "专家"，有自己的系统提示词、推荐 Skill 和工具权限。你可以在 AI 面板顶部切换 Agent。

#### Agent 选择器
**位置**: AI 面板顶部（原来是 "AGENT" 文字，现在是可点击下拉按钮）

显示形式:
```
[🤖 通用助手 ▾]
```

点击后展开 Agent 列表:
```
选择 Agent 角色
─────────────────
🏗️ 故事架构师        ● 强模型
👤 角色设计师         ● 中模型
✍️ 叙事写手           ● 中模型
🔍 一致性检查器       ● 轻模型
🔎 故事探索者         ● 轻模型
🎯 评论者             ● 强模型
📖 读者模拟器         ● 中模型
🎭 角色模拟器         ● 中模型
💡 脑暴者             ● 任意
📋 大纲师             ● 中模型
🎨 风格创建器         ● 中模型
📜 编年史家           ● 轻模型
```

圆点颜色表示推荐的模型档位：红=强 黄=中 绿=轻 灰=任意

#### 13 个 Agent 详解

| Agent | 职责 | 适用场景 |
|-------|------|---------|
| 通用助手 | 全能的 AI 创作助手 | 默认、不想手动切换时 |
| 故事架构师 | 故事结构设计、题材定位、大纲、钩子与反转 | "帮我搭新书架构" |
| 角色设计师 | 角色档案、语言风格、动机链 | "帮我设计主角" |
| 叙事写手 | 正文写作、文风保持、日更续写 | "帮我写第 5 章" |
| 一致性检查器 | 事实冲突扫描、伏笔追踪、设定审计 | "帮我检查有没有矛盾" |
| 故事探索者 | 角色/伏笔/设定快速查询（只读） | "主角目前什么状态？" |
| 评论者 | 深度对抗式批评，只挑问题 | "狠狠批我的稿子" |
| 读者模拟器 | 以读者视角模拟阅读体验 | "读者看到这章什么感觉？" |
| 角色模拟器 | 以角色身份对话 | "我想和主角聊聊" |
| 脑暴者 | 创意发散，生成多样选项 | "帮我脑暴几个情节点子" |
| 大纲师 | 方向序列化为可执行大纲 | "把方向变成具体细纲" |
| 风格创建器 | 分析文风，生成风格参考 | "分析我这篇的风格" |
| 编年史家 | 提取事实更新知识库 | "把新章节更新到知识库" |

#### 智能路由

v0.2.0 支持 4 层自动路由:

- **显式 `/skill` 调用**: 输入 `/novel-draft` → 自动激活叙事写手
- **自然语言触发词**: 输入 "帮我写大纲" → 自动激活故事架构师
- **Skill whenToUse 匹配**: 输入意图被 Skill 注册的 whenToUse 覆盖 → 激活对应 Agent
- **默认 fallback**: 未匹配 → 通用助手

### 2.1.x v0.2.1 新增 — 架构生成专家选择

#### 概念
在生成故事架构（前提/角色图谱/世界观/情节大纲）时，可以指定由哪个 Agent 专家来执行生成。不同 Agent 有不同的创作风格和侧重点。

#### 使用步骤
1. 在架构面板点击任意架构文件（如「故事前提」）
2. 点击「AI 生成」按钮，弹出架构生成确认对话框
3. 在对话框下方找到「选择生成专家」下拉菜单
4. 从 5 个选项中选择：

| 专家 | 风格特点 | 适用场景 |
|------|---------|---------|
| 默认（故事架构师） | 使用系统内置架构模板 | 通用场景，平衡创意与结构 |
| 故事架构师 🏗️ | 浓缩核心卖点，构建冲突链与悬念骨架 | 商业网文，强调开篇钩子与爽点密度 |
| 大纲师 📋 | 擅长结构化推演，严密的情节节奏编排 | 逻辑严密的多线叙事，伏笔回收 |
| 脑暴者 💡 | 创意驱动，激进的情节设计与反转 | 打破套路，追求创新设定与情节 |
| 通用助手 🤖 | 平衡创意与结构的通用模式 | 保守稳妥，兼容性强 |

5. 勾选要生成的步骤（可单步/多步），可选填补充指导
6. 点击「确认生成」，工作流日志会显示 `🎯 使用专家 Agent: 🏗️ 故事架构师`

####  internals
- 选择的 Agent 会注入 `context.data.agentRole` 到工作流每个步骤
- 每个步骤调用 LLM 时使用该 Agent 的 `systemPrompt` 覆盖默认模板
- 实现真正意义上的"专家驱动"生成，而非仅改个名字

### 2.2 v0.2.0 多 Agent 协作体系（原 2.1 内容顺延）

#### 概念
v0.2.0 内置 Skill 从 5 个扩展到 28 个。每个 Skill 是一个知识包（系统提示词片段），可通过 `/skill-name` 命令在对话中调用。

#### 调用方式
- 在 AI 对话中输入 `/` 触发命令菜单
- 直接输入 `/skill-name`（如 `/novel-outline`）
- Agent 可自动推荐和调用关联 Skill

#### P0 核心 Skill（11 个新增）

## 三、典型工作流

### 3.1 新书搭建

1. 创建新项目
2. AI 面板选 "故事架构师"（或用 "帮我搭新书架构" 自动路由）
3. 输入 `/novel-outline` 启动大纲搭建流程
4. 架构师引导确认选题 → 核心设定 → 卷级大纲 → 第1-10章细纲
5. 选 "叙事写手"，输入 `/novel-draft` 开始写正文

### 3.2 日更续写

1. 选 "叙事写手"
2. 输入 `/novel-draft` → AI 自动加载追踪上下文 + 角色状态 + 当前细纲
3. 写正文
4. 写完后选 "编年史家"，输入 `/story-memory` 更新知识库

### 3.3 审稿润色

1. 选 "评论者" → 输入 `帮我审稿` → 获得问题清单
2. 选 "叙事写手" → 输入 `/deai-filter` → 去 AI 味
3. 选 "一致性检查器" → 输入 `/continuity-check` → 检查矛盾

### 3.4 角色开发

1. 选 "角色设计师" → 设计角色档案
2. 选 "角色模拟器" → 输入 `/character-sim` → 和角色对话
3. 选 "读者模拟器" → 输入 `/reader-sim` → 看读者对角色反应

## 五、常见问题

### Q: 如何回到默认模式？
A: 在 Agent 选择器下拉中选 "通用助手"。

### Q: Skill 太多记不住怎么办？
A: 在 AI 对话中输入 `/` 即可看到全部 Skill 列表，按分类排列。

### Q: Agent 会自动切换吗？
A: 会。输入包含触发词（如 "帮我写大纲"）时自动激活对应 Agent。

### Q: 切换 Agent 会丢失对话吗？
A: 不会。切换 Agent 只改变系统提示词，对话历史和会话继续保留。

## 六、v0.2.1 修复说明

### 6.1 架构工作流加固

#### 问题现象
- 角色图谱生成失败 → 整个架构流程中断，世界观和情节大纲也不生成
- AI 返回内容过短（仅 thinking 标签，正文为空）
- 生成的架构内容过于简略（角色仅名字 + 一句话）

#### 修复方案
1. **步骤独立执行**: `continueOnError: true` 标记角色/世界观步骤，单步失败不阻断后续
2. **依赖检查降级**: 情节大纲的依赖检查从 `throw` 改为 `log('⚠️ 警告')`，缺失前置数据时尝试降级生成
3. **空值重试阈值**: 10 字 → 50 字，重试时追加「直接输出正文」提示
4. **提示词字数要求**:
   - 角色图谱：每个角色≥150 字，总计≥800 字
   - 世界观：每个维度≥200 字，总计≥600 字
   - 情节大纲：每个节点≥100 字，总计≥1000 字

### 6.2 数据持久化修复

#### 问题现象
保存项目后关闭重开，AI 生成的故事前提/角色图谱/世界观/情节大纲内容丢失。

#### 根因
`NovelConfig` TypeScript 接口缺少 `synopsis`/`worldbuilding`/`charactersArch`/`premise` 字段，导致：
- AI 通过 `db:project-core-update` 写入 DB 的内容，无法通过 `novelConfig` 回到前端 store
- `project:save` 保存时，这些字段被隐式忽略，DB 中被覆盖为空

#### 修复方案
1. `ipc-channels.ts`: `NovelConfig` 接口新增 4 个架构字段
2. `project-controller.ts`: `project:open`/`project:save`/`project:update-config` 双向映射架构字段
3. 同时兼容旧版字段名（`synopsis` → `coreOutline` 的映射保留）

### 6.3 验证清单

Mac 端测试：
```bash
git pull origin dev
pnpm dev
```

1. **架构生成**: 选择「脑暴者」专家 → 生成 4 步骤 → 工作流日志出现 `🎯 使用专家 Agent: 💡 脑暴者`
2. **步骤独立**: 手动构造角色生成失败场景 → 世界观/情节大纲仍继续执行
3. **持久化**: 生成架构 → 保存项目 → 关闭 → 重开 → 架构内容仍在
4. **内容长度**: 检查角色图谱≥800 字、世界观≥600 字、大纲≥1000 字
